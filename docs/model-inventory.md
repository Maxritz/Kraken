## Update: the IQ family landed (2026-10-06)

The scan above predates the IQ-family dequantizers. ggml types 18 (IQ3_XXS), 19
(IQ1_S), 21 (IQ3_S), 22 (IQ2_S), 29 (IQ1_M) and BitNet's 41 (Q1_0) / 42 (Q2_0)
are now implemented on both the host and the device, so every row below whose
*only* blocker was one of those type ids was corrected in place and the per-arch
counts were adjusted to match. Types 17 (IQ2_XS), 100 and 101 were already
supported and rows that named them as blockers were stale for the same reason.

The verdict column is the loader's *static* decision — supported architecture,
playable role, all formats dequantizable — not a claim that the file was run.
End-to-end runs were made for two files: `Bonsai-27B-Q1_0.gguf` (GPU text
identical to the scalar CPU reference) and `Qwen3.8-27B-GSQ-RCO-IQ2_XS.gguf`
(the same, over IQ3_S/IQ3_XXS/IQ2_S/IQ2_XS/IQ2_XXS/IQ1_S/IQ1_M/IQ4_XS at once).
The rest became loadable by the format work and are still unrun here.

Still refused, and deliberately so: types **102, 104, 107** (no authoritative
block layout exists on this machine) and **142** (layout measured, code map is
not a level map -- four candidates failed; see docs/TODO.md). None guessed. Affected files are `Qwen3.8-Distill-35B-A3B-Coder-Abliterated-Q2KXL_ROCMFPX.gguf`
(102, 107), `ornith-1.0-35B-Q3_0_ROCMFPX.gguf` (102, 104) and
`Ternary-Bonsai-2-27B-PQ2_0.gguf` (142).

Two files are **broken rather than unsupported**, and must not be read as a
missing dequantizer: `Ternary-Bonsai-27B-Q2_0.gguf` and the Q2_0 shard of
`Swift-Qwen3.8-Flash-Next-GSQ-RCO-IQ2_XS-00002-of-00002.gguf`. Their own
tensor-offset table implies 17 bytes per 64 values (2.125 bpw), while the format
their type id names is 18 bytes per 64 values (2.25 bpw; ggml-common.h:
`#define QK2_0 64`, `block_q2_0 { ggml_half d; uint8_t qs[QK2_0/4]; }`). Upstream
llama.cpp rejects the same file with exactly the size this engine computes
(`tensor 'output_norm.weight' has offset 337715200, expected 357580800`), so the
refusal is correct and the file is internally inconsistent.

Not fixed by this work and still the blockers on "support all my models": the
four type ids above, and the `qwen4exp` architecture used by the
`Swift-Qwen3.8-Flash-Next-*` shards.
